<Callout type="insight" eyebrow="Thesis">
  This post proposes a research program for **layered latent memory grafts**: small trainable modules attached to a frozen language model that learn how to organize, update, retrieve, and consolidate memory over time. The end goal is an offline “dreaming” loop: ingest a new corpus of conversations, documents, and interactions; replay it; update a fuzzy latent memory module; and continue practicing correct retrieval through tools.
</Callout>

Large language models have a strange relationship with memory. They appear to know things, but the knowledge is entangled in billions of parameters. They can retrieve documents, but retrieval often behaves like a bolt-on search step rather than an integrated memory system. They can be fine-tuned, but new updates can overwrite old behavior or blur contradictions. They can use tools, but they often need prompt-level scaffolding to know when to call them.

This proposal starts from a simple question:

> Can we build an LLM memory system that learns over time without forcing all knowledge into either raw weights or raw retrieval?

The hypothesis is that memory should be **layered**. Some parts should change every turn. Some should update after every corpus refresh. Some should consolidate slowly. Some should remain explicit and citeable. Some should live in latent space.

The eventual dream looks like this:

```text
new conversations + documents + tool traces
  -> offline replay / dreaming loop
  -> update fast memory
  -> practice retrieval/tool behavior
  -> consolidate stable patterns
  -> preserve exact evidence externally
  -> wake up with a better fuzzy model of the domain
```

But the experimental path should not start there. It should build up from smaller unit tests.

## 1. The literature map

This proposal combines several existing research threads: retrieval-augmented generation, tool-use fine-tuning, LoRA and parameter-efficient adaptation, model editing, routed LoRA, mixture-of-experts, continual learning, meta-learning, temporal QA, and neuroscience-inspired memory consolidation.

### 1.1 Retrieval as explicit memory

Retrieval-augmented generation begins from a practical observation: language model parameters are a poor place to store every fact. RAG combines a pretrained generator with a non-parametric retriever over an external corpus, making knowledge access fresher and more inspectable than pure parametric recall. The original RAG paper framed this as combining parametric and non-parametric memory for knowledge-intensive generation ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401)).

REALM pushed this view further by pretraining with a latent document retriever, explicitly arguing that external retrieval makes knowledge more modular and interpretable than storing everything in weights ([Guu et al., 2020](https://arxiv.org/abs/2002.08909)). RETRO then scaled the idea by conditioning generation on retrieved chunks from a massive database, showing that retrieval can substitute for some parameter count while preserving factual access ([Borgeaud et al., 2021](https://arxiv.org/abs/2112.04426)).

Retrieval gives memory systems several properties that weights alone struggle to provide:

```text
provenance
freshness
editability
deletion
source metadata
explicit contradiction handling
```

But retrieval alone does not solve the memory problem. A retriever can return evidence, but the model still needs to know **when to retrieve**, **what to search**, **how to scope the search**, **which source to trust**, and **how to answer from evidence rather than from stale priors**.

### 1.2 Training models to retrieve and use tools

The next branch of work trains the model to use external memory more intelligently.

ReAct interleaves reasoning and actions, allowing models to interact with external sources such as a Wikipedia API while solving tasks ([Yao et al., 2022](https://arxiv.org/abs/2210.03629)). Toolformer trains language models to decide when to call APIs, what arguments to pass, and how to incorporate the result ([Schick et al., 2023](https://arxiv.org/abs/2302.04761)). Self-RAG trains models to retrieve adaptively and critique both retrieved passages and generated answers with reflection tokens ([Asai et al., 2023](https://arxiv.org/abs/2310.11511)). RAFT fine-tunes models for domain-specific open-book QA by training them to use relevant retrieved documents and ignore distractors ([Zhang et al., 2024](https://arxiv.org/abs/2403.10131)).

This suggests a key design decision:

<Callout type="note" eyebrow="Design rule">
  The LoRA should not primarily memorize the new corpus. It should learn the **ritual of memory use**: when to retrieve, how to query, how to filter evidence, how to handle contradictions, and when to say there is not enough support.
</Callout>

That is why this proposal includes a **protocol LoRA** and, later, a **temporal LoRA**. These adapters are stable behavioral grafts. They teach the base model how to work with memory systems.

### 1.3 LoRA as modular adaptation

LoRA freezes a pretrained model and injects trainable low-rank matrices into selected transformer linear layers. A normal linear projection does:

```text
y = W x
```

With LoRA, the frozen weight stays in place and a low-rank trainable side path is added:

```text
y = W x + B A x
```

The original LoRA paper showed that this can drastically reduce trainable parameters and memory requirements relative to full fine-tuning while preserving downstream quality ([Hu et al., 2021](https://arxiv.org/abs/2106.09685)). QLoRA then made consumer-scale fine-tuning much more practical by backpropagating through a frozen 4-bit quantized model into LoRA adapters ([Dettmers et al., 2023](https://arxiv.org/abs/2305.14314)).

For this proposal, LoRA has two roles:

1. **Experimental proxy for memory**: fast/slow LoRAs can test whether modular timescales help with continual updates.
2. **Long-term interface layer**: protocol/temporal LoRAs can teach stable memory-use behavior while the memory module itself changes.

LoRA is not literally “on top” of the model. It is a trainable side-path inside existing transformer computations. That makes it an attractive graft: small, swappable, cheap, and distributed through the layers.

### 1.4 Model editing and side memory

Model editing asks whether a model’s factual associations can be updated directly without retraining the whole model.

ROME finds evidence that factual associations can be localized in middle-layer feed-forward modules and edited with rank-one updates ([Meng et al., 2022](https://arxiv.org/abs/2202.05262)). MEMIT extends this idea to many edits ([Meng et al., 2022](https://arxiv.org/abs/2210.07229)). These works are important because they show that some factual memories are mechanistically editable.

But direct editing has obvious limits. Edits must generalize to paraphrases without leaking too broadly. They must avoid damaging unrelated behavior. They must support many sequential updates.

SERAC takes a semi-parametric route: store edits in explicit memory and learn when to apply them ([Mitchell et al., 2022](https://arxiv.org/abs/2206.06520)). WISE is even closer to this proposal: it introduces a main memory, a side memory for edited knowledge, and a router that decides which memory to use, arguing that pure parametric editing and pure retrieval both miss part of the reliability/locality/generalization tradeoff ([Wang et al., 2024](https://arxiv.org/abs/2405.14768)).

The lesson is not “edit the base model harder.” The lesson is:

```text
keep the base model stable
add side memory
route into it carefully
preserve explicit evidence when possible
```

### 1.5 Routed LoRA and adapter banks

Recent adapter work is already converging on the idea that small modules can behave like reusable memory shards.

ELDER uses multiple LoRAs plus a router for lifelong model editing. Its key criticism is that discrete mapping from data to parameters is brittle under paraphrase; it instead tries to learn smooth data-adapter associations and includes a deferral mechanism to preserve base capabilities ([Li et al., 2024](https://arxiv.org/abs/2408.11869)). AM-LoRA learns an attentional mixture over LoRA modules for continual learning, using sparse attention to reduce negative interference ([Liu et al., 2024](https://arxiv.org/abs/2409.19611)). MiLoRA treats LoRAs as experts and uses prompt-aware routing computed once before generation to reduce latency ([Zhang et al., 2024](https://arxiv.org/abs/2410.18035)). SoLA, a 2026 paper, encapsulates edits as independent LoRA modules and uses semantic routing to activate or revoke them ([Luo et al., 2026](https://arxiv.org/abs/2603.11239)).

These papers suggest a near-term experimental family:

```text
single LoRA
fast/slow LoRA
routed LoRA bank
temporal-gated LoRA
LoRA + explicit retrieval
```

The open question is whether these modules should store knowledge, route knowledge, or train the model to use another memory system.

### 1.6 MoE and latent routing

Mixture-of-Experts models make routing central. Sparse MoE architectures activate only a subset of expert parameters per token or sequence. Switch Transformers simplified expert routing with top-1 selection ([Fedus et al., 2021](https://arxiv.org/abs/2101.03961)). GLaM scaled sparse expert models for language modeling ([Du et al., 2021](https://arxiv.org/abs/2112.06905)). DeepSeekMoE focuses on finer-grained experts and shared experts to improve specialization and reduce redundancy ([Dai et al., 2024](https://arxiv.org/abs/2401.06066)).

This literature is relevant because it points toward an “everything in latent space” philosophy: route, specialize, compress, and compute inside learned representations rather than explicit symbolic controllers.

A memory expert inside MoE is possible. But it may be the wrong first experiment. A vanilla feed-forward expert trained on memory-heavy data could blur facts and contradictions. A more promising version is a **shared memory expert** or **hybrid retrieval expert**: a route that specializes in temporal scoping, contradiction detection, and retrieval-conditioned synthesis rather than raw factual storage.

### 1.7 Continual learning and the stability-plasticity problem

The memory problem is a version of continual learning. Neural networks tend to catastrophically forget prior tasks when trained sequentially on new ones. EWC reduces forgetting by slowing changes to weights important for previous tasks ([Kirkpatrick et al., 2016](https://arxiv.org/abs/1612.00796)). Progressive Neural Networks avoid forgetting by freezing old columns and adding new capacity ([Rusu et al., 2016](https://arxiv.org/abs/1606.04671)). Replay methods rehearse old examples while learning new ones.

The engineering lesson is simple:

```text
new memory should not update all parameters equally
```

A good memory system needs different plasticities. Some parts should update quickly. Some should consolidate slowly. Some should be protected.

### 1.8 Learning time

A hand-coded fast/slow split is only a starting point. Ultimately, the system should learn what “time” means for its domain.

Time2Vec represents time with learned periodic and non-periodic components ([Kazemi et al., 2019](https://arxiv.org/abs/1907.05321)). Time-aware language models train on text with timestamps so facts can be represented as temporally scoped rather than timeless ([Dhingra et al., 2021](https://arxiv.org/abs/2106.15110)). Temporal knowledge graph work such as Know-Evolve and diachronic embeddings treats entity representations as functions of time ([Trivedi et al., 2017](https://arxiv.org/abs/1705.05742), [Goel et al., 2019](https://arxiv.org/abs/1907.03143)). Temporal Graph Networks maintain node memories over event streams ([Rossi et al., 2020](https://arxiv.org/abs/2006.10637)).

For this proposal, “time” does not only mean wall-clock date. It means:

```text
recency
validity
volatility
source authority
narrative order
staleness
planning-vs-canon
historical-vs-current query intent
```

The goal is to learn a **latent temporal coordinate** that controls adapter activation, update rates, retrieval filters, and consolidation.

### 1.9 Temporal QA benchmarks

TemporalWiki evaluates language models on evolving Wikipedia/Wikidata snapshots and measures whether models acquire updated knowledge while retaining old knowledge ([Jang et al., 2022](https://arxiv.org/abs/2204.14211)). StreamingQA evaluates QA over 14 years of timestamped news articles, showing that retrieval helps rapid adaptation but stale parametric models can still underperform retrained ones ([Liška et al., 2022](https://arxiv.org/abs/2205.11388)). PAT-Questions studies present-anchored questions whose answers depend on the current date ([Chen et al., 2024](https://arxiv.org/abs/2402.11034)).

These benchmarks motivate evaluation categories beyond ordinary QA:

```text
current-state accuracy
historical as-of accuracy
update success
stale-fact suppression
retention of unchanged facts
source grounding
retrieval recall
contradiction handling
```

### 1.10 Neuroscience: useful analogy, not proof

The neuroscience grounding is strongest at the level of computational principles.

Complementary Learning Systems theory argues that the brain uses fast hippocampal-like learning for pattern-separated episodes and slower neocortical learning for distributed structure ([Blakeman and Mareschal, 2019](https://arxiv.org/abs/1905.02636)). Benna and Fusi model biological memory as interacting fast and slow variables, where memories enter fast variables and are progressively transferred into slower variables ([Benna and Fusi, 2015](https://arxiv.org/abs/1507.07580)). Hippocampal replay and sharp-wave ripples are associated with memory consolidation during rest and sleep. Predictive coding frames the brain as maintaining a model that predicts incoming signals and updates on prediction error.

The analogy should be used carefully:

The biologically inspired idea is not that transformers should copy the brain. It is that useful memory systems often separate:

```text
fast episodic traces
slow semantic consolidation
replay / dreaming
prediction error
attention / gating
source-specific recall
```

## 2. Core hypothesis

The core hypothesis is:

<Callout type="insight" eyebrow="Hypothesis">
  A frozen base LLM augmented with layered, trainable memory grafts can adapt to evolving corpora more efficiently and reliably than pure RAG, single LoRA fine-tuning, or direct model editing, if exact evidence remains external while fuzzy temporal structure is learned in latent space.
</Callout>

A stronger version:

> Offline replay over conversations, documents, and interactions can update a fast latent memory module and train a protocol/temporal LoRA to practice correct retrieval, eventually consolidating stable patterns into slower memory without overwriting the base model.

The design does not require every memory to be explicit. It also does not force every memory into weights. Instead:

```text
explicit retrieval = exact evidence
latent grafts = fuzzy structure and routing
LoRA = stable memory-use behavior
replay = consolidation
```

## 4. Architecture: build up to the dream

The full system is too complicated to test at once. The research program should build in stages.

### Level 0: frozen base plus retrieval

```text
Base LLM
  + external retriever
  + reranker
  + citations
```

This is the standard baseline. It provides exact evidence and source grounding, but does not update the model’s fuzzy representation of the domain.

### Level 1: protocol LoRA

```text
Base LLM
  + Protocol LoRA
  + retriever
```

The protocol LoRA is trained on traces:

```text
question -> decide whether to retrieve -> query tool -> inspect evidence -> answer / defer
```

This tests whether a small adapter can make RAG behavior more reliable.

### Level 2: fast/slow LoRA as the first memory proxy

```text
Base LLM frozen
  + Slow LoRA  (stable memory)
  + Fast LoRA  (recent memory)
```

This is the first real memory experiment. The slow adapter learns stable structure. The fast adapter receives new updates. Periodically, stable behavior is distilled from fast into slow.

```text
new corpus batch
  -> train fast LoRA
  -> evaluate update and interference
  -> distill stable fast behavior into slow LoRA
  -> decay or reset fast LoRA
```

This is not the final system. It is the smallest test of the central claim: different plasticities should help with evolving knowledge.

### Level 3: learned temporal-gated LoRA

Manual fast/slow memory is still a hyperparameter. A stronger experiment learns the temporal coordinate.

```text
query/chunk hidden state
  -> temporal encoder
  -> z_time
  -> layer gates
  -> activate LoRA deltas differently by temporal state
```

```text
y_l = W_l x_l + g_l(z_time) * B_l A_l x_l
```

This tests whether the system can learn what “time” means: recency, volatility, staleness, source status, and query intent.

### Level 4: separate memory module

Once LoRA proxies work, introduce a separate latent memory module.

```text
Base LLM
  + protocol / temporal LoRA
  + semantic memory graft
  + retriever
```

The LoRA teaches the model how to use memory. The memory module holds corpus-specific fuzzy state.

### Level 5: memory compiler graft

Now add the compiler:

```text
messy corpus
  -> Memory Compiler Graft
  -> initial memory slots / gates / source weights / temporal coordinates
  -> memory module trains quickly
```

The compiler is meta-trained across synthetic corpora so it learns how to initialize memory from messy, contradictory data.

### Level 6: dreaming loop

Finally, the dream:

```text
new conversations + docs + interactions + tool traces
  -> offline replay
  -> train fast memory
  -> practice retrieval/tool use
  -> test contradictions and stale traps
  -> consolidate stable patterns
  -> update slow memory / protocol behavior only if needed
```

## 5. Experimental program

### Experiment 1: Does protocol LoRA improve RAG behavior?

Train a small QLoRA adapter on synthetic and real retrieval traces.

Inputs:

```text
question
retrieved docs, including distractors
tool schemas
source metadata
```

Targets:

```text
retrieve or not
which query to issue
which source filters to apply
which evidence to cite
when to refuse or say unknown
```

Baselines:

```text
Base + RAG
Base + RAG + reranker
Base + protocol LoRA + RAG
```

Metrics:

```text
retrieval decision accuracy
retrieval recall@k
citation support
answer accuracy
unsupported-answer rate
distractor resistance
```

Expected result: protocol LoRA should improve evidence use and deferral behavior, especially when distractors or stale sources are present.

### Experiment 2: Fast/slow LoRA over evolving synthetic facts

Construct synthetic corpora with evolving facts:

```text
T0: Mira leads Project Atlas. Launch is June 1.
T1: Launch moves to June 15.
T2: Noah replaces Mira as lead.
T3: Atlas is renamed Atlas Search.
T4: Mira returns as advisor, not lead.
```

Train:

```text
T0: train slow LoRA
T1..Tn: freeze slow, train fast on updates
periodically: distill stable fast behavior into slow
```

Baselines:

```text
single LoRA continual fine-tuning
single LoRA with replay
fast-only LoRA
slow-only LoRA
fast+slow LoRA without consolidation
fast+slow LoRA with consolidation
rank-matched normal LoRA
```

Metrics:

```text
new fact acquisition
retention of old still-valid facts
suppression of stale facts
historical as-of accuracy
interference on unrelated QA
```

Key question:

> Does dual-timescale adaptation beat a single rank-matched LoRA?

### Experiment 3: Learned temporal-gated LoRA

Replace manual fast/slow assignment with a temporal encoder that gates layer-wise LoRA deltas.

```text
z_time = TemporalEncoder(prompt_or_chunk)
g_l = sigmoid(MLP_l(z_time))
y_l = W_l x_l + g_l * LoRA_l(x_l)
```

Train on synthetic corpora containing:

```text
latest facts
historical facts
future plans
superseded notes
contradictory docs
flashbacks / out-of-order chapters
```

Compare:

```text
normal LoRA
manual fast/slow LoRA
fixed depth schedule LoRA
learned temporal-gated LoRA
learned temporal-gated LoRA + replay
```

Key question:

> Can the model learn what “time” means rather than receiving time as a hand-coded hyperparameter?

### Experiment 4: Synthetic story and project worlds

Before real corpora, generate controlled fake worlds.

Each world contains:

```text
chapters or memos
wiki summaries
planning notes
future outlines
retcons
source contradictions
character or stakeholder knowledge gaps
```

Each world has hidden ground truth:

```text
what is true now
what was true at time t
what each actor knows
which notes are plans vs canon
which sources supersede which
```

Question buckets:

```text
current-state QA
as-of-time QA
what-changed QA
stale-trap QA
planned-vs-canon QA
source-grounded QA
character-knowledge QA
contradiction resolution
```

This avoids the noise of real news while still testing temporal memory.

### Experiment 5: Memory module and dream replay

Introduce a separate memory module. During the day, the retriever stores exact evidence. Offline, the dream loop trains the memory module and protocol LoRA on replayed traces.

```text
experience buffer:
  conversations
  documents
  retrieved chunks
  user corrections
  tool calls
  contradictions
  unresolved questions

nightly replay:
  generate training traces
  train fast memory
  practice retrieval/tool use
  test stale traps
  consolidate stable structure
```

A key design point: the LoRA continues to practice correct retrieval. The dream loop should not train the model to hallucinate the answer from latent memory when evidence is needed. It should train:

```text
better fuzzy representation
better retrieval policy
better evidence discipline
```

### Experiment 6: Memory compiler meta-learning

The compiler is trained across many synthetic corpora.

```text
for corpus C_i:
  reset memory module
  compiler reads C_i
  compiler outputs initialization / gates / source weights / distilled traces
  memory module trains for k steps
  evaluate on hidden questions
  backprop into compiler
```

In the cheap version, the compiler does not generate all weights. It generates:

```text
initial memory slots
temporal coordinates
source trust weights
contradiction clusters
example weights
training schedule
small LoRA/graft initialization deltas
```

This is an amortized learner: it learns how to build memory from messy corpora.

## 7. Why this might work

First, PEFT is already strong enough to alter model behavior cheaply. LoRA and QLoRA make it plausible to train multiple small modules around a frozen base.

Second, retrieval protects exact evidence. This avoids the core weakness of pure parametric memory: no provenance.

Third, routed LoRA and MoE research suggest that latent routing over specialized modules can work, although routing remains fragile.

Fourth, continual learning and neuroscience both suggest that memory systems benefit from multiple timescales rather than one homogeneous update rule.

Fifth, offline replay is a natural fit for AI systems. Conversations, documents, tool calls, and corrections can be replayed into training traces without needing to interrupt inference.

## 8. Why this might fail

<Callout type="alert" eyebrow="Failure modes">
  The main risk is not that the model cannot learn anything. The main risk is that it learns the wrong thing: shortcuts, stale priors, overconfident latent recall, or routing patterns that look good on synthetic corpora but fail in real messy domains.
</Callout>

Likely failures:

```text
fast memory does all the work and slow memory never consolidates
slow memory absorbs stale or uncertain facts too early
temporal gates learn keyword shortcuts instead of temporal structure
latent memory blurs contradictions that retrieval would keep separate
router collapses to one path
retrieval practice is forgotten during parametric replay
synthetic corpora do not transfer to real corpora
rank-matched single LoRA performs just as well
```

The most important ablation is therefore simple:

```text
fast/slow or temporal-gated LoRA
vs
single LoRA with the same total rank and replay budget
```

If the proposed structure does not beat that, the rest of the architecture is not justified yet.

## 9. Why not pure RAG, pure LoRA, or pure MoE?

Pure RAG keeps evidence clean but may fail to develop a usable latent model of the domain. Pure LoRA can adapt cheaply but buries evidence and can blur time. Pure model editing can handle local facts but struggles with many updates, scope, and rollback. Pure MoE gives conditional compute but is expensive to train and hard to interpret.

The proposed middle ground:

```text
retrieval stores exact evidence
LoRA teaches memory behavior
grafts learn fuzzy latent state
replay consolidates stable patterns
routers decide when to trust which path
```

## 10. The smallest publishable experiment

The smallest credible paper is not the full dream system. It is:

> Temporal-gated LoRA for evolving knowledge.

Train and compare:

```text
1. normal LoRA
2. normal LoRA + replay
3. manual fast/slow LoRA
4. learned temporal-gated LoRA
5. learned temporal-gated LoRA + replay/consolidation
```

Evaluate on synthetic evolving corpora and TemporalWiki-style updates.

Report:

```text
new fact acquisition
old fact retention
stale suppression
historical QA
source-grounded retrieval behavior
interference
training time
adapter size
inference latency
```

If this works, it justifies moving to separate memory modules and the dream loop.

## 11. The longer-term dream

The end state is a system that can ingest a growing life of interactions.

```text
raw experience:
  user conversations
  docs
  code changes
  decisions
  retrieved evidence
  failed tool calls
  corrections
  contradictions

sleep / dream:
  replay recent experience
  generate retrieval traces
  detect stale beliefs
  train fast memory
  practice tool use
  consolidate stable patterns
  preserve evidence externally

wake:
  answer with a better fuzzy representation
  retrieve more precisely
  know when not to trust itself
```

This is not just “more memory.” It is a memory lifecycle.

The important philosophical stance is:

> Put fuzzy structure into latent space. Keep exact evidence explicit.

That is the line between useful memory and uninspectable hallucination.

## 13. Open questions

1. Is LoRA expressive enough to learn temporal routing, or is a separate residual graft required?
2. Can learned temporal gates generalize beyond keyword shortcuts like “now” and “before”?
3. Does consolidation from fast to slow memory preserve behavior better than replay alone?
4. Can a memory compiler trained on synthetic corpora transfer to real documents and conversations?
5. How much exact evidence must remain external to avoid hallucination?
6. Can retrieval practice be maintained while latent memory improves?
7. Is a memory expert inside MoE better than an external memory graft, or just harder to train?
8. What is the right unit of memory: fact, claim, episode, chunk, conversation, tool trace, or latent state?
9. How should user corrections enter the dream loop?
10. How do we evaluate a fuzzy representation without overfitting to explicit labels?

## 14. Conclusion

The proposal is not to make an LLM remember everything. That would recreate the weaknesses of parametric memory: stale facts, weak provenance, and hard deletion.

The proposal is to give the model a memory lifecycle:

```text
explicit evidence for exact facts
latent grafts for fuzzy structure
LoRA adapters for memory-use behavior
replay for consolidation
retrieval practice for discipline
learned temporal coordinates for evolving truth
```

Start small. Train a protocol LoRA. Then fast/slow LoRA. Then learned temporal-gated LoRA. Then a memory module. Then a compiler. Then the dream loop.

If the early experiments fail, the full architecture is probably overbuilt. If they work, the path is clear: build a system that sleeps on new experience, updates its fuzzy world model, and wakes up better at knowing when to remember, when to retrieve, and when not to trust itself.
